# v1.4.1 results (29 Oct 2026): hex lattices, tori, quadrics, rotation, distributed materials

Everything below comes from `validate.log`, `tests.log` and
`sector_seeds.log` in this folder. 2M histories per validate run; OpenMC
0.16 in 400 batches; pass rule as before (no tally chi2 with p < 0.001,
no single value with |z| > 3.29).

## What is new

- `HexLattice` in both orientations, 2D and 3D.
- `XTorus`, `YTorus`, `ZTorus`, with circular or elliptical tubes.
- `Quadric`, meaning any second-order surface.
- Rotational periodic walls: two planes through the z axis.
- Distributed materials: one cell with a different material in each place
  it is used.
- A bug fix since v1.0. Outside a lattice's array, OpenMC repeats the
  outer universe element by element. We used one frame for the whole
  outside, which is right only when the outer universe is uniform (as in
  every test problem until now).

## New problem `hexcore`: two hex lattices

Fuel and rod pins in a 3D 'y' lattice below a 2D 'x' lattice. Below, the
outer universe has a small rod sphere in every would-be element. Locating
20,000 random points matches OpenMC on every one.

## New problem `sector`: rotational quarter with tori, a quadric and distributed pins

A 90-degree quarter of a cylinder with rotational walls at x = 0 and
y = 0. Inside are a 3 x 3 pin lattice whose pin has nine distributed
materials, an elliptical ZTorus ring cut by both walls, a small XTorus,
and a tilted ellipsoid written as a general Quadric. Locating 20,000
random points matches OpenMC on every one.

| quantity | plain MC | exact balls | OpenMC |
|---|---|---|---|
| leakage | 0.107293 (z +2.10) | 0.107498 (z +2.83) | 0.106735 +- 0.00022 |
| cell flux (6 bins, incl. the distributed pin) | 1.05 | 1.53 | |
| material flux (7 bins) | 0.91 | 1.27 | |
| mesh flux (3310 bins) | 0.98 | 0.99 | |
| time | 203 s | 227 s | 62 s |

Both pass. The two leakage z values point the same way against the same
reference, so I reran with new seeds against a fresh OpenMC run at
another seed (`sector_seeds.log`). OpenMC gave 0.107275 +- 0.00023,
plain MC z -0.94 and +0.04, and exact balls z -0.50 and -0.16. The first
reference was low by about 2 sigma, so this was noise.

Sector is slow (203 s) because the big shell region tests two tori on
every flight. A torus flight first cost 11 us: a general polynomial
solver (`np.roots`). I replaced it with a bracketed search between the
quartic's turning points, which costs 0.46 us (a sphere costs 0.03 us).
Against a fine-grid reference on 90,000 rays it misses no crossing, and
the worst difference is 2e-10 cm.

## The other seven problems

- **Sphere, slab, curved, lattice3d, cask, tilted:** identical numbers to
  v1.4.0. The logs differ only in timings and an OpenMC ID warning.
- **Nested:** changed within its error bars, because of the outer-universe
  fix (its outer universe is uniform, but flights now also stop at the
  would-be element walls). Leakage z is -2.34 for plain MC (was -3.20)
  and -3.18 for exact balls (was -3.36). Both now pass. The nested OpenMC
  reference was shown to be low at 10M histories in v1.2.
- **Slab:** the known plain MC depth-mesh item (chi2/dof 1.766, noise
  since v1.2) is still there, so validate's overall line still reads FAIL
  for that one item.

## Unit tests: 138 pass (30 new)

- Torus and quadric values equal OpenMC's own.
- Flights skip no crossing and land on the surface.
- Torus distance is never too large, and within 0.06 cm of a fine grid of
  torus points.
- Quadric distance is never too large. It is exact for a plane and tight
  near a sphere.
- Normals equal the gradient.
- A rectangular lattice with a non-uniform outer universe locates like
  OpenMC.
- Distributed materials follow OpenMC's own instance order (`cell.paths`)
  in a cell reached three ways: a universe cell, a lattice and a
  translated universe cell. That model includes a void entry.
- A rotational quarter cylinder gives the same leakage as the full
  cylinder.
- The rotation angle follows OpenMC's rule.
- Refusals: a wrong-length fill list, a wall off the z axis, a torus
  whose tube reaches the axis.

## Limits (all in GAPS.md)

- A distributed fill with a void entry runs here, but OpenMC 0.16 stops on
  one in multigroup mode (measured), so it is checked only by unit test.
- Rotational walls follow OpenMC's assumption that the problem lies on
  the + side of both planes. If a model breaks that, both codes turn
  particles the wrong way, silently.
- Quadric distances are a lower bound, so balls near a quadric are smaller
  than they need to be (still exact, just slower).
- Refused:
  - a torus whose tube reaches the axis
  - rotational walls off the z axis
  - a distributed cell inside an outer universe
