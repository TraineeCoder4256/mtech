## Point detectors (`detcheck.log`, `core/detectors.py`)

The next-event estimator is scored from every isotropic emission (source
sites and scatters). Inside a ball, the unseen scatters are scored as
sigma_s x the ball's flux at 4 profile points. This was Phani's idea 1-A.

**A bias found and fixed.** The first detector check
(`detcheck_before_fix.log`) had balls low against plain MC at every
detector: z -4.43, -3.60, -2.32 and -1.09 (2-6%).

- Cause: a ball's walk is conditioned on scattering at least once. The
  straight flights it leaves out carry track but no scatters, so
  "scatters = sigma_s x flux" undercounts.
- Fix: each ball also scores the missing term, sigma_s (P_straight /
  P_ball) x a straight flight's flux.
- The derivation is in `core/detectors.py`.

After the fix:

| check | result |
|---|---|
| exact: point source in two absorbing shells, 3 points | rel err 5e-10, 1.8e-15, 5e-10 |
| balls vs plain MC, void cavity | z -0.81 |
| balls vs plain MC, outer void | z -0.07 |
| balls vs plain MC, in the medium (r0 0.3 cm) | z -1.30 |
| balls vs plain MC, deep in the medium (r0 0.3 cm) | z +0.11 |
| vs OpenMC void-sphere average (20M), cavity | plain z +1.86, balls z +1.13 |
| vs OpenMC void-sphere average (20M), outer void | plain z +0.17, balls z +0.13 |

OpenMC 0.16 has no point detector. Its reference here is the average
flux in a small void sphere around the point, which differs from the
point value only at second order in the sphere's radius.

## The slab item: the 20M reference found the cause, not a cure

What was run:
- `slab_ref.log`: OpenMC at 20M histories (2000 x 10k, seed 777). Against
  it, the slab passes in plain MC and exact balls, at 2M (seed 5) and
  20M (seed 11).
- `slab_corr.log`: 40 independent runs.
- `neff_probe.log`: the effective-bins test.
- `validate.log`: the full validate, now with the slab's reference at
  20M (seed 101).

What it showed:
- **The depth bins move together.** The correlation is +0.88 between
  neighbours and +0.37 ten bins apart. That is about 6 independent bins
  among 60.
- **So their chi2/dof is far noisier than the rule assumes.** Over 40
  runs of a correct code it had sd 0.64 (the rule assumes 0.18), and 7 of
  the 40 would fail the rule.
- **The failing run is one overall shift.** Plain MC at seed 1, the run
  that has failed since v1.2, has a total flux 2.15 sigma low (a 1-in-30
  event), and every depth bin moves with it.
- **It still fails against the 20M reference.** In the v1.6 validate it
  scores chi2/dof 2.16 (depth) and 2.24 (depth1d). Against the seed-777
  20M reference it had passed (1.27).
- **A rule that counts effective bins passes it.** That rule is
  Satterthwaite's effective degrees of freedom, with the correlation
  measured from our own runs. Under it the results are:

  | run | p with independent bins | p with effective bins |
  |---|---|---|
  | v1.6 depth | 5e-7 | 0.040 |
  | v1.6 depth1d | 1e-4 | 0.039 |
  | v1.5 depth | 2e-4 | 0.096 |

  Exact balls pass it as they are (chi2/dof 0.74).

## Robustness suite (`robust.log`; `robust_first.log` is the first run)

30 models were built at random, each with:
- 1 to 4 objects: spheres, shells, cylinders, boxes, cones, tilted
  cylinders, tori and lattices;
- random vacuum, reflective, white or periodic faces;
- random sources and tallies.

Results: **25 PASS, 5 refused cleanly, 0 FAIL, 0 ERROR.** The 5 refused
are the ones given an unsupported feature: an albedo, a collision
estimator (twice), a fission score and a horn torus. Each refusal names
the feature.

Found along the way:

- **The first run had 2 ERRORs.** OpenMC itself crashed (a segfault) on a
  multigroup 'scatter' tally with a void cell. This was already known
  (v1.1.3), and it is confirmed: the same models run once the score is
  dropped. The generator now leaves that score out when a void cell
  exists.
- **2 models failed on the first try and passed at 5x.**
  - Model 12 failed narrowly (p 9e-4: chance).
  - Model 26 failed strongly (mesh chi2/dof 3.1). The cause
    (`model26.log`) is deep bins behind a shield, where OpenMC's analog
    run scored almost nothing. One face current is 0 +- 0 in OpenMC,
    while our implicit capture measures a small value. The z-score then
    reads 4-6.
  - This is a reference-statistics problem of the same family as the
    slab item, not a code error.

## Edge cases (`tests/test_edge_cases_v160.py`, 10 tests)

**One real bug found and fixed.** A source exactly on a surface lay in
no cell. The source was redrawn for ever: the test hung. Such a site is
now moved 1e-8 cm along its direction, which is how OpenMC picks the
side. Two smaller changes came with it:
- a source that can never be accepted stops after about 20 rounds;
- a model in which nothing absorbs and nothing leaks is refused.

The other tests pass as they are:
- empty tallies give 0, not NaN;
- balls in a 1e-6 cm gap give the same answer as without the gap;
- zero-volume cells score nothing and change nothing;
- a near-void (sigma 1e-9) is exact;
- sigma 100 /cm is exact for an absorber and balanced for a scatterer.

## Limits (all in GAPS.md)

- Point detectors are refused in three cases:
  - with reflective, white or periodic walls;
  - with non-isotropic sources;
  - with a FileSource.
- Inside a scattering material a detector needs r0 > 0 for finite
  variance, at a bias of order r0. This is the same as in MCNP.
- Detectors with the trained network are not checked yet.
- The pass rule's two blind spots, correlated bins and reference bins
  with almost no counts, remain. The fix is Phani's decision.
